# Connected service deployment

The public previews and Android APKs are offline demos. They do not need cloud accounts or collect messages. A real private inbox requires the connected server generated by `node scripts/build.mjs`.

## Deploy one country at a time

1. Run the build and tests. Choose one folder under `live/`, for example `live/luna-harbor/`.
2. In your Cloudflare account, create a **new** D1 database and private R2 bucket for this app. Never bind one of these apps to the existing Rekha database or bucket. Review the provider's current costs before creating resources.
3. Copy that app's `wrangler.example.json` to `wrangler.json`. Replace `REPLACE_WITH_NEW_DATABASE_ID` with the actual new database ID. Confirm the database and bucket names match your new resources. The template deliberately contains no existing account ID or route.
4. Apply the generated `schema.sql` to the new database. It starts conversations in **manual** reply mode.
5. Set a unique, strong owner password locally. Compute its SHA-256 hash and store that hash as the Worker secret `ADMIN_PASSWORD_HASH`. Never commit the plaintext password or hash. Keep the password in your password manager.
6. Deploy the generated `worker.mjs` using the provider's current CLI or dashboard. The Worker bundles its own customer and owner assets. Its scheduled cleanup removes inactive chats after 30 days.
7. Verify HTTPS, `/api/health` (including the expected `app` ID), customer signup and an actual owner reply. Open `https://YOUR-APP-HOST/admin` for your private inbox. Test two customers to verify that their messages and attachments stay separate.
8. Repeat with fresh resources and a different password for each app. Do not run different country bundles against the same D1 database: session cookie names are shared by the inherited runtime, so isolation depends on separate origins and databases.

The included schema is for fresh databases only. There is no migration promise for existing services.

## Replies and media

The owner can send personal replies immediately after deployment. AI modes are optional. To use a real provider, set server-side `AI_MODE=live`, `AI_BASE_URL` (HTTPS API base), `AI_MODEL` and secret `AI_API_KEY`, then select auto-reply or assisted replies in the owner panel. AI mode without a configured provider fails instead of silently inventing a human response. `AI_MODE=demo` explicitly enables localized sample replies for testing.

The current inheritance retains a three-completed-reply preview allowance and a **no-charge** preview unlock. There is no real checkout or currency charge. A production payment flow requires a separately verified provider integration for each intended market.

The owner media library and automated reply/video flow begin empty and disabled. Add only media you own or may use, and provide the wording appropriate to each app's supported languages before enabling a flow. Do not reuse Rekha testimonials as evidence for a different practitioner or service. The advanced inherited flow editor exposes English/Hindi-era fields; the new app's default flow text is localized, but expanded multi-language flow editing is not included.

## Android after hosting

The supplied APKs intentionally bundle offline previews. They do not become connected merely because the server has been deployed. For a connected release, replace the Android virtual-origin preview loader with the exact app HTTPS origin, keep navigation restricted to that origin, implement requested camera/microphone/file handling, and retest devices. Preserve each application's package ID and signing certificate for updates. Do not publish an untested hosted WebView as a completed mobile launch.

## Data handling

Use HTTPS. Customer and owner sessions use separate HttpOnly cookies; mutations validate origin. The server and owner can read messages. R2 attachment access is checked against the conversation. No keys, PINs, customer exports, databases or signing files belong in this repository. Account recovery, MFA, production monitoring, regional legal review, secure backup policies and a verified chart engine are not included.
