# Customer activity

Open **Owner tools → Customer activity** in the private admin website or existing admin Android app. It shows consenting visitors' static button/page clicks, screen visits, media playback and customer app foreground opens. Filter by website/app, time window, current customer or a visitor's timeline. Reports require the existing owner session.

The public collector is first-party and optional. No visitor identifier, event queue or activity requests exist before the visitor chooses Allow. No thanks leaves all app features available. Change the choice through app privacy settings or the website privacy page. The collector never transmits typed values, messages, names, passwords, payment details, click coordinates, filenames or media URLs. The server associates consenting customer activity with a chat only through its existing HttpOnly session cookie.

Download starts are separate anonymous operational totals: successful full customer APK GET responses, excluding HEAD, Range, missing files and admin APKs. They do not prove completed downloads or installation. These totals use complete UTC days intersecting the selected window, and cannot be attributed to a customer. Android first opens mean the first shared run on that installation; foreground returns count as app opens. They depend on activity sharing and the native wrapper marker, and do not count every installed phone. Browser controls, offline exits and permission dialogs can affect signals.

Events have UUIDs for idempotent retries. Batches contain at most 20 events and 8 KiB, with a 200-event memory queue and bounded retries. Tracking cannot delay chat sends. Indexed reporting is limited to 50 rows per page and the most recent 10,000 events per summary, visibly marked when sampled. To preserve headroom on the current Cloudflare plan, collection reserves at most 5,000 valid event entries per UTC day; duplicate retries can consume this budget. The dashboard shows budget usage and pauses. Chat and downloads keep working when collection pauses or fails.

Apply `cloudflare/migration-activity.sql` to the existing D1 database before releasing the worker. It only creates activity tables and indexes. The schema includes the same additive definitions for new local databases. Minute cron ticks remove up to 1,000 expired events, with bounded daily cleanup of anonymous download totals. Reports exclude events older than 30 days immediately. Chat deletion cascades linked events; anonymous website events remain until expiry/cleanup. Existing bindings, resources, APK signing and cron schedules remain unchanged.

When submitting to Google Play, disclose optional app interaction analytics and its random identifiers in Data safety, consistent with the published privacy policy. This feature does not establish store approval.
